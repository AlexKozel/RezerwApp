# Поток записи

Связано: `DECISIONS.md` (D-010…D-017, D-031), `DATA_MODEL.md`.

## 1. Диаграмма

```
Клиент: услуга → вариант → время (слоты с учётом длительности и буфера)
  → контакты → OTP (один раз на номер/устройство)
  → согласия: [политика отмен ✓] [Regulamin/политика ✓] [здоровье, если нужно ✓]
  ├─ клиент доверенный И нет оплаты по услуге → confirmed
  └─ иначе → pending (hold, hold_expires_at)
        ├─ мастер одобрил → confirmed
        ├─ мастер отклонил → rejected (слот свободен)
        └─ время вышло → expired (слот свободен, клиенту сообщение)

confirmed → completed | no_show | cancelled_by_client | cancelled_by_master | rescheduled
```

## 2. Статусы

| Статус | Занимает слот | Кто переводит |
|---|---|---|
| `pending` | Да, до `hold_expires_at` | Система создаёт |
| `confirmed` | Да | Мастер или система (гибридный режим) |
| `rejected` | Нет | Мастер |
| `expired` | Нет | Система по таймеру |
| `cancelled_by_client` | Нет | Клиент (по политике) или мастер от имени клиента |
| `cancelled_by_master` | Нет | Мастер |
| `completed` | История | Мастер |
| `no_show` | История | Мастер |
| `rescheduled` | Старая запись закрывается, создаётся новая связанная | Клиент или мастер |

## 3. Hold

- Длительность по умолчанию 2 часа, настраивается мастером (D-017).
- Клиент видит таймер и инструкцию. Через 30 минут после создания заявки мастеру уходит напоминание, если он не ответил.
- Освобождение выполняется фоновой задачей по `hold_expires_at`; ограничение БД не требует очистки, пока статус `pending` или `confirmed`, поэтому задача обязана менять статус вовремя.
- Мастер может вручную изменить длительность слота перед одобрением. Если новое время пересекается с другой записью, система отклоняет изменение с понятным сообщением.

## 4. Резервационная оплата (MVP: `manual_blik`)

- Режимы на услугу: `нет` / фиксированная сумма / процент; для `всех` или `только новых клиентов` (D-010).
- Клиент видит сумму, номер BLIK мастера и **код платежа** (например `A7K2`) для комментария.
- Мастер проверяет перевод в банке и нажимает «Одобрить» или «Отклонить».
- Сумма ограничена потолком (D-014) со значением по умолчанию, утверждённым юристом.
- Деньги идут напрямую мастеру. Платформа в расчётах не участвует (D-010).

Судьба оплаты (D-013):

| Событие | Результат |
|---|---|
| Отмена клиентом не позже дедлайна | Оплата возвращается или переносится на новую дату (по политике мастера) |
| Отмена клиентом после дедлайна | Удерживается мастером (если включено), иначе возвращается |
| Отмена мастером | Возвращается полностью |
| Неявка клиента | Удерживается мастером (если включено) |

Платформа фиксирует решение в `payment_requests.status`, но физический возврат делает мастер.

## 5. Перенос и отмена клиентом

- Ссылка в напоминании и в подтверждении ведёт на страницу записи без регистрации (подпись токеном).
- До дедлайна доступны «Перенести» и «Отменить». После дедлайна вместо переноса доступна кнопка «Связаться с мастером».
- Максимум переносов задаётся политикой (по умолчанию 1-2).
- Перенос создаёт новую запись, связанную с исходной, оплата переходит на новую запись без повторного платежа.
- Применяется версия политики, действовавшая на момент исходного бронирования (D-015).

## 6. Уведомления

| Событие | Клиент | Мастер |
|---|---|---|
| Заявка создана | Инструкция по оплате, таймер | Push о новой заявке |
| +30 минут без ответа | — | Напоминание |
| Подтверждена | Подтверждение, ссылка управления | — |
| Отклонена / истекла | Сообщение, предложение другого времени | — |
| За 24 часа до визита | Напоминание: «Подтверждаю» / «Перенести» / «Связаться» | — |
| Отмена клиентом | Подтверждение | Push |
| Освободился слот (v1.1, лист ожидания) | Предложение занять окно | — |

Порядок каналов: Web Push → Messenger/Viber/Telegram → email → SMS (D-035).

## 7. Гонки и конфликты

- Два клиента на один слот: побеждает первая транзакция, вторая получает ошибку и предложение выбрать другое время (D-031).
- Офлайн-правка мастера против онлайн-заявки: сервер побеждает, мастер видит уведомление о конфликте (см. `ARCHITECTURE.md`, раздел 6).
- Повторный клик «Одобрить»: операция идемпотентна.

## 8. Защита от злоупотреблений

- OTP и Turnstile для публичных форм, лимиты на номер и IP.
- Blacklist мастера: клиент видит нейтральное «Нет свободных мест», причина не раскрывается.
- Лимит одновременных `pending` заявок на номер у одного мастера.

## 9. Метрики для «сколько вы сэкономили» (MVP)

- Количество записей с резервационной оплатой, которые завершились визитом.
- Сумма удержанных оплат при неявке.
- Количество отклонённых/истёкших заявок и причина.
- Условное сравнение с комиссией маркетплейса (только как оценка, с понятной формулой в интерфейсе).
