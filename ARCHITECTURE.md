# Архитектура

Связано: `DECISIONS.md` (D-030…D-037), `DATA_MODEL.md`, `BOOKING_FLOW.md`.

## 1. Стек

| Слой | Выбор | Примечание |
|---|---|---|
| Клиентский виджет | Next.js (React), SSR | Быстрая загрузка в in-app браузерах Instagram/TikTok/Facebook. Mobile-first. |
| Кабинет мастера | PWA на React | Service Worker, IndexedDB. Capacitor-обёртка при необходимости (D-034). |
| Backend | NestJS (TypeScript) | Модульный монолит. Общие типы с фронтом (monorepo). |
| БД | PostgreSQL | `btree_gist`, Row-Level Security, `tstzrange`. |
| Кэш и очереди | Redis, BullMQ | Сессии, лимиты, OTP, отложенные уведомления, освобождение hold. |
| Файлы | S3-совместимое хранилище в ЕС | Портфолио, референсы тату (v1.1). Антивирусная проверка, лимиты размера. |
| Хостинг | ЕС (страна определяется владельцем проекта) | Для RODO избегать передачи данных в третьи страны. |

## 2. Модули backend

1. `auth` — вход мастера (email+пароль или passkey, magic link), сессии, OTP клиента.
2. `accounts` — Account, подписка, тарифы, лимиты SMS, счета.
3. `locations` — адреса, подключение Independent-мастеров к Location (D-021).
4. `catalog` — услуги, варианты (длительность, цена, буфер), шаблоны вертикалей.
5. `availability` — рабочие часы, блоки времени, расчёт свободных слотов.
6. `bookings` — заявки, статусы, hold, перенос, отмена (см. `BOOKING_FLOW.md`).
7. `policies` — политики отмен (версионируются), согласия клиента.
8. `clients` — клиентская база, заметки, blacklist, импорт CSV, экспорт.
9. `notifications` — каналы, шаблоны по языкам, очередь, журнал, учёт SMS.
10. `analytics` — метрики «сколько вы сэкономили», маржа услуг.
11. `audit` — журнал доступа к персональным данным.
12. `admin` — поддержка, тарифы, глобальная аналитика (без доступа к содержимому заметок).

## 3. Защита от двойной записи

Конфликт слотов решается ограничением БД (D-031), а не только оптимистичной блокировкой:

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;
-- slot = диапазон [начало, конец + буфер)
ALTER TABLE bookings ADD CONSTRAINT bookings_no_overlap
  EXCLUDE USING gist (staff_id WITH =, slot WITH &&)
  WHERE (status IN ('pending','confirmed') AND capacity = 1);
```

Приложение ловит нарушение ограничения и возвращает клиенту «слот уже занят, выберите другое время».
Для `capacity > 1` (групповые занятия, v2) проверка выполняется отдельной логикой в транзакции.

## 4. Изоляция данных

- Каждая таблица с пользовательскими данными содержит `account_id`.
- PostgreSQL Row-Level Security: приложение выставляет `app.account_id` на соединение/транзакцию, политики фильтруют строки.
- Автотесты межтенантного доступа обязательны (попытка прочитать данные чужого Account должна падать).
- Админ-доступ только через отдельную роль с журналированием.

## 5. Шифрование

- Транспорт: TLS везде.
- Данные в покое: шифрование хранилищ провайдером (базовый уровень).
- **Поле заметок и другие чувствительные поля:** шифрование на уровне приложения (envelope encryption): ключ данных на Account, мастер-ключ в KMS. Расшифровка только в запросах авторизованного пользователя этого Account.
- Бэкапы шифруются, срок хранения бэкапов учитывается в политике удаления данных.
- Режим для психологов и терапии (D-026): клиентское сквозное шифрование, ключ у мастера. Не в MVP.

## 6. PWA и офлайн (D-033, D-034)

Что работает офлайн в MVP:
- просмотр расписания на окно ±14 дней, контактов, не-медицинских заметок;
- смена статусов визитов (пришёл, не пришёл, завершён) и добавление заметок в виде очереди событий.

Правила:
- Очередь изменений отправляется при событии `online`, при открытии приложения и по таймеру в открытом приложении. Background Sync не используется как основной механизм.
- Создание записи офлайн = черновик, проверяется сервером при синхронизации. При конфликте сервер выигрывает, мастер получает уведомление.
- Кэш шифруется (WebCrypto, ключ из PIN/биометрии через WebAuthn). Удалённая очистка при выходе, автоочистка по таймауту.
- Данные о здоровье по умолчанию не кэшируются.

Известные ограничения iOS (проверить спайком, gate G1 в `ROADMAP.md`):
- Push работает только после добавления на домашний экран.
- IndexedDB может очищаться системой при долгом неиспользовании.
- Background Sync отсутствует.

Если gate G1 не пройден, переход на Capacitor (та же веб-кодовая база, нативная оболочка, APNs). Для этого уже сейчас:
- push за интерфейсом `PushProvider` (реализации: WebPush, позже APNs/FCM);
- хранилище офлайн-данных за интерфейсом `OfflineStore`;
- никаких зависимостей от API, недоступных в WebView.

## 7. Уведомления

- Очередь BullMQ, повторные попытки, идемпотентность по ключу события.
- Порядок каналов (D-035): Web Push → Messenger/Viber/Telegram → email → SMS.
- Шаблоны хранятся по языкам (PL/UK/RU/EN), язык берётся из профиля клиента или языка виджета.
- Учёт SMS: леджер на Account (включено, использовано, докуплено), блокировка отправки при исчерпании (кроме OTP и критичных уведомлений по настройке).
- Триггеры: создание заявки, подтверждение, отклонение, истечение hold, напоминание за 24 часа с кнопками «Подтверждаю»/«Перенести»/«Связаться», отмена.

## 8. i18n

- Библиотека i18n на фронте и бэке, ключи сообщений вместо строк в коде.
- Формат дат и валюты по локали, часовой пояс Account.
- Юридические тексты (Regulamin, политика) хранятся версионированными документами по языкам. Юридически приоритетная версия: польская.

## 9. Безопасность и эксплуатация

- OWASP ASVS как чек-лист. Rate limiting на OTP и создание заявок. Turnstile на публичных формах.
- Секреты в менеджере секретов, не в репозитории.
- Журнал аудита доступа к клиентским данным.
- Логи без персональных данных и без содержимого заметок.
- Мониторинг и алерты (ошибки, очередь, задержка уведомлений), процедура реагирования на инциденты (см. `LEGAL_CHECKLIST.md`).
- Обязательный внешний обзор безопасности перед обработкой реальных данных клиентов.

## 10. Тестирование и CI

- Юнит-тесты на расчёт слотов, политику отмен, статусы.
- Интеграционные тесты с реальным PostgreSQL: гонки по слоту (параллельные запросы), RLS, истечение hold.
- E2E для виджета на мобильных вьюпортах, ручной чек-лист для in-app браузеров Instagram/TikTok/Facebook.
- CI: линтер, типы, тесты, миграции на пустую БД.
